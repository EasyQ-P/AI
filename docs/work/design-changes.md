## 1. Python 3.12 → 3.9 (trainer · retrieval)

- **설계서:** 10.1 개발 환경 표에 "Python 3.12, uv 가상환경"으로 되어 있다.
- **변경:** trainer · retrieval은 **Python 3.9 문법**으로 쓴다. 로컬 개발은 3.12로 하고, CI는 3.9에서도 검사한다.
- **이유:** 학과 서버(ceprj)는 Python 3.9.21이고, 가상환경을 만들 수 없다.
  - 그래서 패키지를 서버에 맞춰 `pip install --user`로 설치한다.
  - 서버에 이미 있는 torch 2.1.2와 transformers 등은 그대로 쓴다.
- **영향:**
  - 백엔드(auth · backend · worker)는 3.12 그대로 둔다.
  - 공용 패키지 `retrieval`은 3.9와 3.12 양쪽에서 돌아가므로 백엔드에서도 그대로 쓸 수 있다.
- **수정할 문구:** 10.1 표의 학습서버 행을 이렇게 바꾼다.
  > Python 3.9(학과 서버 기본, 가상환경 미사용) · uv(로컬 개발 · lock)

## 2. 레지스트리 DB: PostgreSQL → SQLite 파일

- **설계서:**
  - 8장 머리말: "학습서버 레지스트리 DB (학과 서버, PostgreSQL)"
  - 10.1 표: "레지스트리 DB | PostgreSQL"
- **변경:** 레지스트리 DB를 학과 서버의 **SQLite 파일 하나**로 둔다. 예: `/home/t26112/easyq-data/registry/registry.db`
  - 따로 떠 있는 DB 서버 프로세스가 없다. 학습서버 API가 파일을 직접 읽고 쓴다.
- **이유:** 학과 서버 규칙("웹/DB는 AWS")상 학과 서버에 DB 서버(PostgreSQL)를 띄울 수 없다.
  - AWS RDS로 옮기는 안도 검토했다.
  - 하지만 학습 기록이 SSH 터널 상태에 좌우되고, 백엔드 팀이 따로 준비할 것도 생겨서 제외했다.
- **바뀌지 않는 것:**
  - 테이블 10개(`reg_` 접두어), 컬럼, 역할은 8.2.38 그대로다.
  - 레지스트리가 학습 쪽 정보의 원본이라는 점도 그대로다.
  - 서비스 DB(RDS)에 관리자 화면용 복사본을 두는 것도 그대로다.
- **구현 방침:**
  - SQLAlchemy와 Alembic을 쓰고, PostgreSQL 전용 기능(JSONB, 배열 타입 등)은 쓰지 않는다.
  - DB에 쓰는 건 학습서버 API 프로세스만 한다. 학습 · 평가 작업은 진행 상황을 파일로 남기고, API가 읽어서 기록한다.
  - 날마다 파일을 백업한다.
  - 관리자가 SQLite도 안 된다고 하면 연결 주소(`REGISTRY_DB_URL`)만 바꿔 AWS RDS로 옮긴다. 코드는 그대로다.
- **수정할 문구:**
  - 8장 머리말: "학습서버 레지스트리 DB (학과 서버, SQLite 파일)"
  - 10.1 표: "레지스트리 DB | SQLite (학과 서버 규칙상 DB 서버 미사용)"
- **영향:** 백엔드는 레지스트리 DB에 직접 접속하지 않고 학습서버 API(7.4)로만 묻는다. 그래서 바뀌는 게 없다.

## 3. 판정 모델: GPU 상주 → 필요할 때만 GPU에 올림(임대 방식)

- **설계서:** 판정 추론 프로세스가 서빙 버전의 fp16 모델을 학과 서버 GPU에 **상주**시킨다. 관련 위치는 다음과 같다.
  - 2.3 T-18
  - 4장 서빙
  - 6.1 구성 표 "fp16, GPU 상주"
  - 7.4.26
  - 10.1 "GPU 상주 판정 추론"
- **변경:** 판정 모델은 **임대(lease) 방식**으로 GPU에 올린다(백엔드 v1.4 제안, 11/27 수락).
  - 백엔드 워커는 LIVE 강의가 하나라도 있는 동안(또는 강연 직전 미리) 1분마다 "적재 유지"(R1 `POST /judge-model/keepalive`)를 보낸다.
  - 학습서버는 요청을 받으면 모델이 없을 때 올리고, 마지막 요청 뒤 5분이 지나면 스스로 내린다. 별도의 "내림" 호출은 없다.
  - 같은 요청을 여러 번 보내도 결과가 같다(멱등). 응답은 `{loaded, loading, expires_at}`이다.
  - 학습 · 평가 · 변환이 GPU를 쓰는 중이면 609를 돌려주고 올리지 않는다.
  - 모델이 올라가 있지 않을 때 판정 요청(7.4.26)이 오면 기다리지 않고 바로 611을 돌려주고(R3), 서비스는 지금 설계대로 Sonnet 단독 판정(LLM_ONLY)으로 처리한다.
  - 상태 확인 API(7.4.1)는 `model_loaded`를 함께 돌려준다(R2, 11/27 반영).
  - 7.4.1의 `status`는 미적재여도 `ok`로 둔다. 설계서는 `degraded = 모델 미적재`였으나 임대 방식에서는 강연이 없을 때 미적재가 정상이라 항상 `degraded`가 되므로, 적재 여부는 `model_loaded`로만 알린다(11/27).
- **이유:** 학과 서버 가이드가 GPU 독점을 금지한다. 다른 팀과 같이 쓰는 GPU라 계속 점유하면 안 된다. 임대 방식은 강연 종료 호출이 빠지거나 워커가 죽어도 5분 뒤 자동으로 해제되어, 시작 · 종료를 따로 알리는 방식보다 안전하다.
- **바뀌지 않는 것:**
  - 판정 방식(fp16, 후보 20개 한 배치)
  - 800 ms 제한과 넘으면 LLM_ONLY로 대체하는 것
  - 학습 · 평가 · 변환이 GPU를 쓰는 동안 609를 돌려주는 규칙
- **백엔드 영향 (합의됨):**
  - 워커에 1분 주기 keepalive를 추가한다.
  - 모델을 올리는 데 몇 초~수십 초 걸린다. 그동안 들어온 질문은 611 → LLM_ONLY로 처리된다.
  - 서빙 어댑터는 이미 10초마다 상태 확인 API를 부른다(6.4). 여기서 `model_loaded`도 함께 받는다.
- **수정할 문구:** "GPU 상주"를 "필요할 때 GPU 적재(임대 방식, 마지막 요청 5분 뒤 해제)"로 바꾸고, 7.4.1 출력에 `model_loaded`를 추가하고 `status`의 `degraded = 모델 미적재` 정의를 지우며, 7.4에 keepalive API를, 6.4 서빙 흐름에 적재 · 해제 단계를 추가한다.

## 4. 학습서버 파일 위치: `/data/easyq` → `/home/t26112/easyq-data`

- **설계서:** 데이터셋 · 체크포인트 · 모델 · 로그를 `/data/easyq/` 아래에 둔다(7.4.29 파일 표).
- **변경:** 학과 서버에는 `/data` 폴더가 없다(2026-11-26 확인). 그래서 팀 계정 홈 아래 `/home/t26112/easyq-data/`에 둔다.
  - 그 아래 구조(`datasets/` · `checkpoints/` · `exports/` · `models/` · `evaluations/` · `logs/`)는 설계 그대로다.
  - SQLite 장부는 `registry/registry.db`에 둔다.
- **확인한 것:** `/home`은 서버 자체 디스크(xfs, 여유 5.4 TB)다. 네트워크 디스크가 아니라 SQLite를 둬도 된다.
- **구현:** 코드는 설정값 `DATA_ROOT`만 읽는다. 학과 서버 `.env`에 `DATA_ROOT=/home/t26112/easyq-data`를 넣는다.
- **주의:** 팀 공용 계정이라 이 폴더를 다른 팀원이 지우거나 옮기지 않도록 공유한다.

## 5. AI Hub 다운로드 · 가공 위치: 학과 서버 → 본인 PC

- **설계서(3.1.3):** AI Hub 데이터는 "학과 서버의 본인 계정 폴더에만 둔다". 재가공 데이터도 AI Hub 데이터로 취급한다.
- **변경(PR #12, 엄윤종):** 데이터를 받은 본인 PC에서 다운로드 · 샘플링 · 변환을 하고, 결과만 학과 서버로 올린 뒤 PC의 원본 · 결과를 지운다(`scripts/data/aihub_sample.py`).
- **같은 것:** 최종 보관 · 학습은 학과 서버에서만 한다. 서버에 올린 뒤 서버 밖으로 내보내지 않는다. 외부 API(임베딩 등)로 보내지 않는다. 팀원끼리는 코드만 공유한다.
- **다른 것:** 원본 · 재가공본이 가공하는 동안 본인 PC에 잠시 있다.
- **이유:** 엄윤종에게 확인 필요(AI Hub 다운로드 프로그램이 서버에서 돌지 않는 것으로 추정). 코드 주석이 가리키는 결정 기록 `docs/notes/AIHub_다운로드_정리.md`가 레포에 없어 PR #12에 함께 올려 달라고 요청한다.
- **수정할 문구:** 3.1.3 신청 · 보관 행에 "다운로드 · 가공은 신청자 본인 PC에서 하고, 결과를 학과 서버로 옮긴 뒤 PC 사본은 지운다"를 추가한다.

## 바뀌지 않는 것 (확인용)

- 학습서버 API(7.4)는 설계대로 학과 서버 `127.0.0.1:8000`에만 열고, EC2가 SSH 터널(22번 포트)로만 접근한다.
  - 외부에 공개하는 웹이 아니라 학습 · 추론을 제어하는 로컬 API라서 학과 서버 규칙과 맞다고 판단했다.
- 판정 추론은 `127.0.0.1:8001`에서 돌고, 7.4.26으로 호출한다.
- 서비스 웹 · 서비스 DB(RDS) · S3는 모두 AWS에 있다.
- 학습 데이터(AI Hub 포함) · 체크포인트 · 모델 파일은 학과 서버 밖으로 나가지 않는다.

## 서버 관리자에게 확인할 것

1. 학습 · 추론을 제어하는 작은 로컬 API(GPU 미사용, localhost 전용)를 상시 띄워 둬도 되는지
2. 학습서버가 쓰는 SQLite 파일(DB 서버 아님)을 둬도 되는지
3. 강연 시간대에 GPU 0번에 판정 모델(약 1~2 GB)을 올려 둬도 되는지
