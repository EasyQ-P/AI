## 2.2 데이터분석의 요구사항

본 절에서는 판정 모델의 학습과 평가에 필요한 데이터가 갖추어야 할 내용과 특성을 식별하고 정의한다. 판정 모델은 질문 하나와 근거 하나의 쌍을 입력으로 받아 답변 가능 점수를 출력하므로, 필요한 데이터는 서비스에 실제로 들어오는 질문과 근거의 모습에서 정한다.

### 2.2.1 데이터 식별

서비스에 들어오는 질문은 청중이 모바일 웹에서 입력한 한국어 질문이며, 전문용어 일부가 영어로 섞인다. 근거는 강연자가 올린 교안의 조각과, 강연자의 발화를 STT로 바꾼 30초 단위 발화 청크다. 교안은 영어 비중이 높은 전공 자료가 많고, 발화는 한영 혼용 구어체다. 이로부터 학습 · 평가 데이터가 갖추어야 할 내용과 특성을 다음과 같이 식별한다.

1. **질문-근거 쌍**: 데이터의 한 단위는 질문 하나와 근거 하나의 쌍이며, 근거는 교안 조각과 발화 청크를 모두 포함한다.
2. **세 가지 판정 라벨**: 판정 모델은 AI가 답할 질문과 강연자에게 넘길 질문을 가려야 한다. 따라서 모든 쌍에 답변 가능 / 근거 부족 / 의견 질문 라벨이 있어야 하며, 의견 질문은 근거가 있어도 이관 대상이다.
3. **어려운 오답**: 주제가 같아 질문과 비슷해 보이지만 답을 담고 있지 않은 근거가 실제 서비스에서 가장 헷갈리는 경우다. 이런 쌍이 학습 데이터에 들어 있어야 오답 즉답률을 낮출 수 있다.
4. **언어 조합**: 한국어 질문 + 영어 교안, 한국어 질문 + 한영 혼용 발화가 중심이고, 영어 강연을 위한 영어 질문 + 영어 근거를 일부 포함한다.
5. **강좌 · 강의 식별**: 같은 강좌의 내용이 학습과 시험에 함께 들어가면 성능이 부풀려진다. 쌍마다 출처 강좌와 강의를 기록해 강좌 단위로 나눌 수 있어야 한다.
6. **출처 · 이용 조건**: 공개 데이터는 라이선스와 이용 조건이 다르다. 출처와 라이선스를 기록하고, 처리 위치에 제한이 있는 데이터(AI Hub)는 쌍마다 구분한다.

평가에는 판정 모델 시험셋과 측정용 부가 데이터(사람 전사본, 바꿔 쓴 질문, 발화에만 답이 있는 질문)가 필요하다. 판정 모델 시험셋은 서비스 평가셋으로 함께 쓰며, 서비스와 같이 질문마다 검색 후보 20개를 붙인 질문 단위 데이터로 만든다. 재학습에는 운영 중 생기는 피드백을, 질문자와 강연자가 모두 학습 활용에 동의한 경우에만 개인정보 없이 라벨 후보로 모은다.

### 2.2.3 학습 · 평가 데이터 분리 원칙

학습 데이터와 평가 데이터는 출처를 나누어 구성한다. 평가 결과가 실제 서비스 성능을 반영하고, 이용 조건이 다른 데이터가 평가 과정에 섞이지 않게 하기 위해서다.

1. **강좌 단위 분할**: 같은 강좌의 쌍은 학습 · 검증 · 시험 중 한 셋에만 둔다. 학습에서 본 강좌로 시험하면 처음 보는 강연에서의 성능을 잴 수 없기 때문이다.
2. **보강 데이터는 학습에만**: SQuAD 2.0과 AI Hub 데이터는 근거 부족 패턴과 데이터 양을 보강하는 데만 쓰고, 검증셋과 시험셋에는 넣지 않는다. 임계값(τ)을 정하는 검증셋을 시험셋과 같은 구성(한국어 질문 중심)으로 맞추기 위해서다.
3. **AI Hub 데이터의 처리 범위**: AI Hub 데이터는 원본과 재가공본 모두 해외 서버 · 클라우드 · API를 거칠 수 없다. 그래서 학과 서버 안에서만 처리하고, 시험셋에 넣지 않는다. 그래야 시험셋에서 해외 API를 거치는 베이스라인 3(Sonnet 단독)과 근거 충실도를 모두 측정할 수 있다.
4. **시험셋은 사람의 라벨**: 시험셋 라벨을 LLM이 붙이면 성능이 정답이 아니라 LLM 라벨과의 일치도가 되고, Sonnet 단독 베이스라인의 점수가 부풀려진다. 따라서 시험셋은 사람이 라벨을 붙이고 2인이 교차 검수한다.
5. **평가셋은 질문 단위**: 서비스는 검색 후보 20개 중 최고 점수로 판정하므로, 검증 · 시험셋도 같은 형식으로 만들어 τ와 오답 즉답률을 서비스와 같은 조건에서 잰다.
6. **평가용 강의의 피드백은 학습에 쓰지 않는다**: 검증 · 시험 강좌와 자체 녹음 강의로 연 강연의 피드백이 학습셋에 들어가면 검증 · 시험 결과가 부풀려진다.

출처별 사용 범위는 3.1.1, AI Hub 처리 규칙은 3.1.3, 분할 규칙은 3.3.4에서 정의한다.

## 2.3 AI학습서버의 요구사항

AI학습서버는 학과 서버에서 동작하는 별도 FastAPI 서버로, 판정 모델(bge-reranker-v2-m3 파인튜닝)의 데이터셋 관리 · 학습 · 평가 · 배포 · 추론을 담당한다. 데이터셋 · 체크포인트 · 모델 패키지 · 평가 리포트는 모두 학과 서버에 두고, 서비스 서버(AWS EC2)에는 요약과 지표만 조회 API로 넘긴다. 서비스 서버와는 SSH 터널로만 연결된다(EC2 호스트의 Docker bridge 주소:9000 → 학과 서버 localhost:8000, 7.1).

학습서버 기능은 호출하는 쪽에 따라 세 경로로 쓰인다.

- **관리자 웹 기능**(조회, 검수 라벨 반영, 학습 · 재학습과 중단, 배포 · 롤백): 관리자 웹 → backend 관리자 API → 학습서버 API
- **서비스 자동 처리**(판정 추론, 평가용 교안 조각 조회): worker가 학습서버 API를 직접 호출
- **AI 파트 운영 기능**(데이터셋 등록, 재수집, 학습 파라미터, 수동 평가 · 비교 · 변환 · 등록, 버전 메모 · 삭제, 장애 조회): AI 담당자가 학과 서버에 SSH로 접속해 같은 API를 localhost로 호출

개발할 기능은 7개 모듈, 22개 상세기능이다.

| T-11 | 배포모듈 (L3) | fp16 변환 (fp32 체크포인트 → fp16 모델 패키지, 추론 시간 측정) | F8-6 | AI |
| T-12 | 배포모듈 (L3) | 모델 버전 등록 (등록 조건 확인 · 학과 서버 저장 · 지표 메타 등록) | F8-6 | AI |
| T-13 | 배포모듈 (L3) | 서빙 버전 전환 (배포 기준 확인) | F9-6 | AI |
| T-14 | 배포모듈 (L3) | 롤백 (이전 서빙 버전 또는 LLM_ONLY) | F9-6 | AI |
| T-15 | 모델 관리모듈 | 모델 버전 목록 · 상세(지표 · ROC) 조회 | F9-5 | AI |
| T-16 | 모델 관리모듈 | 모델 버전 메모 수정 · 삭제 | F9-6 | AI |
| T-17 | 모델 관리모듈 | 작업(수집 · 학습 · 평가 · 변환) 목록 · 상태 조회 | F8-7 | AI |
| T-18 | 추론 인터페이스모듈 | 판정 추론 (질문 + 근거 후보 20개 → 근거별 점수 · 판정) | F4-2, F8-8 | AI · 백엔드 |
| T-19 | 추론 인터페이스모듈 | 서버 상태 확인 (서빙 어댑터 상태 확인) | F8-8 | AI |
| T-20 | 장애기록모듈 | 장애 기록 (수집 · 학습 · 변환 · 배포 · 추론 오류 저장) | F8-7 | AI |
| T-21 | 장애기록모듈 | 장애 기록 조회 | F8-7 | AI |
| T-22 | 데이터셋 관리모듈 (L1) | 평가용 교안 조각 목록 제공 (서비스의 평가용 강의 자동 판정용) | F12-1 | AI · 백엔드 |

기능별 처리 원칙은 다음과 같다.

- **작업 실행**: 장시간 작업(T-04 수집, T-05 학습, T-09 평가, T-11 변환)은 요청 즉시 작업 번호(job_id)를 돌려주고 백그라운드에서 실행한다. 학습 · 평가 · 변환 작업은 GPU에서 한 번에 하나만 실행한다. 학습 요청은 학습이 끝난 뒤 fp16 변환 → 평가 → 등록 → 서빙 버전과의 비교까지 같은 작업 번호로 이어서 실행한다(7.4.7).
- **판정 추론**: T-18은 강연 중 실시간으로 호출되므로 학습 작업과 분리된 추론 프로세스가 서빙 버전의 fp16 모델을 GPU 메모리에 상주시켜 처리하며, 학습이 진행되는 중에도 응답한다. 응답이 800 ms를 넘기거나 실패하면 서비스 서버가 그 질문만 LLM_ONLY(Sonnet 단독 판정, F4-3)로 판정한다.
- **데이터 경계**: AI Hub 데이터와 그 가공본은 학과 서버 밖으로 보내지 않으며, 학습서버 API 응답에도 AI Hub 원문을 넣지 않는다.
- **인증**: 모든 API는 API 키(X-API-Key) 인증을 거치며, 학습서버 포트는 외부에 열지 않는다.

## 2.4 AI서비스 유스케이스 모델

EasyQ의 기능은 세 영역으로 나뉜다. 강연자와 청중, 관리자에게 서비스를 제공하는 AI서버, 판정 모델의 학습 데이터를 만들고 운영 중 피드백을 모으는 데이터수집, 판정 모델을 학습 · 평가 · 배포하는 AI학습서버다. 본 절에서는 사용자용과 관리자용 유스케이스 다이어그램에 세 영역을 구분하여 표시하고, 각 유스케이스와 기능 명세의 대응 관계를 정의한다.

유스케이스 번호는 영역별 접두어를 쓴다. UC-S는 AI서버, UC-D는 데이터수집, UC-L은 AI학습서버의 유스케이스이며, 2.5절 · 2.6절의 요구기능 정의와 6장의 기능 설계는 이 번호를 기준으로 작성한다. 유스케이스는 UC-S 28개, UC-D 8개, UC-L 7개로 모두 43개다.

### 2.4.2 사용자용 유스케이스

[그림: 사용자용 유스케이스 다이어그램 (a) 강연자 — 다시 그림]
[그림: 사용자용 유스케이스 다이어그램 (b) 청중 · 회원 — 다시 그림]
[그림: 사용자용 유스케이스 다이어그램 (c) 데이터수집 · AI학습서버 — 다시 그림]

사용자용 유스케이스 다이어그램은 액터별로 세 장으로 나눈다. (a)는 강연자, (b)는 청중 · 회원 · 비회원, (c)는 AI 담당자의 유스케이스이며, 데이터수집 영역의 UC-D06은 (a)와 (b)에 함께 표시한다. 강연자와 회원인 청중은 회원의 하위 액터로 회원의 유스케이스도 쓴다. 게스트 청중은 회원 유스케이스를 쓰지 않는다.

비회원은 이메일로 받은 인증 코드를 입력해 회원가입을 하고(UC-S01), 회원은 로그인 · 로그아웃을 하며 비밀번호를 잊으면 이메일로 받은 링크로 재설정한다(UC-S02).

강연자는 강연을 만들고 교안을 업로드한 뒤 입장 QR을 발급한다. 교안을 업로드하면 텍스트 추출, 청킹, 임베딩, 용어 사전 생성으로 이루어진 교안 처리(UC-S20)가 함께 수행된다. 강연자는 강연마다 음성 처리(STT)에 동의한 뒤 음성을 전송하고(UC-S08), 음성은 실시간 STT로 텍스트가 되어 30초 단위 발화 청크로 저장된다(UC-S21). 강연자는 라이브 대시보드에서 이관된 질문을 교안 페이지별 · 공감순으로 확인하며 답변 완료를 처리한다. 강연을 종료하면 요약 노트가 생성된다(UC-S23). 강연자가 종료하지 않아도 LIVE 시작 후 12시간이 지나면 같은 방식으로 자동 종료된다.

청중은 QR로 입장하여 서비스 이용(필수)과 학습 활용(선택)에 동의한 뒤 질문을 작성한다. 질문을 입력하는 동안 비슷한 공개 질문이 먼저 표시되어 공감으로 합칠 수 있고, 새 질문을 제출하면 질문 판정 · 답변 생성(UC-S22)이 수행된다. 처리 중에는 "근거를 찾는 중", "답변을 작성하는 중"의 진행 상태가 표시된다. 판정 모델이 답할 수 있다고 판정한 질문은 근거 위치와 함께 질문자에게만 AI 답변이 전달되고, 그렇지 않은 질문은 공개 목록으로 이관되어 강연자에게 전달된다. 회원인 청중은 참여한 강연의 내 질문 · AI 답변 · 요약 노트를 계정을 삭제할 때까지 내 보관함에서 다시 본다(UC-S18, UC-S19).

강연자의 AI 답변 철회(UC-S11, 사유 선택), 청중의 AI 답변 평가(UC-S16), 판정 과정의 이관(UC-S22)이 발생하면 데이터수집 영역의 피드백 라벨 후보 수집(UC-D06)이 함께 수행되어, 질문자와 강연자가 모두 학습 활용에 동의한 경우에만 개인정보를 제외한 익명 라벨 후보가 저장된다.

AI 담당자는 공개 데이터를 수집하여(UC-D01) 질문-근거 쌍을 만든다(UC-D02). 학습 · 검증용 질문은 질문 생성 LLM으로 합성하고, 시험셋에는 합성 질문과 팀이 직접 쓴 질문을 함께 쓴다. 라벨링 · 검수(UC-D03)는 데이터셋마다 달리하여, 시험셋은 2인이 전수 교차 검수하고 검증셋은 1인이 전수 확인하며 학습셋은 무작위 10%를 검수한다. 검수한 데이터는 강좌 단위로 학습 · 검증 · 시험에 나누고(UC-D04) 버전으로 등록한다(UC-D05).

등록된 데이터셋은 AI학습서버의 판정 모델 학습(UC-L01)에 쓰인다. 평가 · 임계값 결정(UC-L02)에서는 서비스와 같은 fp16 모델로 검증셋에서 질문 단위 답변 임계값(τ)을 정하고, 시험셋에서는 그 값을 고정한 채 성능을 잰다. 이후 모델은 fp16 변환 · 버전 등록(UC-L03)을 거친다.

### 2.4.3 관리자용 유스케이스

[그림: 관리자용 유스케이스 다이어그램 — 다시 그림]

관리자는 서버에서 생성한 운영자 전용 계정으로 로그인한다. AI서버 영역에서는 회원을 조회하고 계정을 정지 · 복구하며, 진행 중에 문제가 생긴 강연(세션)을 강제 종료하고, AI 답변 비중 · 이관 비율 · 응답 시간 · API 비용 같은 운영 지표와 월 API 예산 사용률을 확인한다. 회원에게 공지를 올리고 1:1 문의에 답한다(UC-S28).

데이터수집 영역에서는 학습 데이터의 라벨 분포와 버전을 확인하고(UC-D07), 운영 중 수집된 라벨 후보를 승인 · 수정 · 제외한다(UC-D08). 판정 모델이 이관한 질문은 판정 점수가 임계값 바로 아래인 것부터 검수하고, 답변 가능으로 확정할 때는 검수자가 정답 근거를 골라 판정 모델이 놓친 질문을 학습 데이터로 돌린다. 검수된 라벨은 AI학습서버 영역의 재학습(UC-L05)에 반영된다. 재학습으로 만든 새 버전은 같은 시험셋으로 평가해 기존 버전과 비교하고(UC-L06), 9.2의 등록 조건을 만족하고 같은 시험셋에서 서빙 중인 버전보다 ROC-AUC가 같거나 높을 때만 배포한다(UC-L07). 배포 후 운영 지표가 나빠지면 이전에 서빙했던 버전이나 LLM_ONLY(판정 모델 없이 Sonnet 단독 판정)로 롤백한다.
